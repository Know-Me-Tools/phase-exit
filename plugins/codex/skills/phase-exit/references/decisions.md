# Evidence and bounded continuation

Verify the adopted revision, original receipt hashes, runner and exact command,
terminal result, source and fixture identities, configuration, platform and image
digest. Preserve failed receipts. A repaired group's success cannot certify other
groups or another architecture. Carry evidence only through explicit valid
dependencies; unknown impact requires review.

Before a gate, confirm the full implementation inventory exists and all planned
production behavior, persistence, contracts, fixtures and documentation are done.
An unfinished item keeps the boundary closed across sessions. The engine's action
authorization is exact; do not replace arguments, executable or working directory.
The engine evaluates authority but never launches acceptance commands for you.

Hooks may veto completion or propose evidence/amendments. They cannot override
mandatory predicates or add release requirements. Required hook failure prevents
certification; optional notification failure is recorded. Installed hooks are
trusted executable code, not a sandbox. Respect host recursion markers and permit
at most the bounded continuation the adapter authorizes.

For UAR release work: local gates precede source/tag/image publication. Run the
full approved program against each published child digest, then publish release
receipts and issue updates. A tag alone is not success. Preserve immutable tags
when published acceptance fails. A genuine unavailable supervisor setup is a
BLOCKED result, not a waived criterion or successful release.

When stopping, cite the exact receipt or prerequisite and permitted next step.
Record discoveries and amendments separately. Do not allow a model explanation,
high probability, exhausted budget or silence to become an adoption or pass.
