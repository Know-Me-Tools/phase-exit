# Phase contract

Turn the operator's approved scope into a finite, sourced criterion inventory.
Read the active waypoint, complete plan/task ledger and existing adoption first.
Count actual criterion IDs; preserve contradictory historical counts as evidence.

Read [the contract workflow](references/workflow.md) when creating or amending a
contract. Use the installed CLI's versioned schemas and interface documentation;
never invent a command flag or silently drop a required field.

Every criterion needs a source, expected outcome, applicable stage, dependencies
and observable evidence predicate. Every permitted acceptance action needs exact
executable/arguments and its boundary. Separate implementation, local acceptance,
publication, published-artifact acceptance and release receipts so completion is
not circular. Record exclusions, external prerequisites and bounded attempts.

Models may propose. Only explicit operator adoption changes authority. Produce a
readable amendment diff and evidence-invalidation map; retain old revisions,
failed receipts and rationale. Classify discoveries before proposing scope.
Do not convert an optional improvement into a release condition.

Complete all phase production behavior, fixtures, documentation and packages
before any verification. Record the implementation-complete inventory first.
This workflow never treats an individual fix as permission to test.

The uncomfortable limit: adoption records and hashes are audit evidence, not
proof against a privileged process. Do not promise universal defect absence.
